# Threat model

Status: approved by the owner on 2026-10-30. `SPEC.md` lists the build work for each MVP 0.5 row.

This file lists the workflow nodes and threat nodes from two articles and from the owner's grill. It splits them by job: underground or arkan. underground owns the sandbox, the broker, and the merge gate. arkan owns the agents: tasks, schedules, memory, budgets, and output.

Sources:

- A: [How the Claude Code team does code review](https://claude.dev/blog/solving-code-review-at-anthropic/), 2026-10-15, read 2026-10-29.
- B: [Building effective agent automations](https://claude.dev/blog/building-effective-agent-automations/), 2026-10-08, read 2026-10-29.
- G: the owner's grill on the product brief, 2026-10-29 and 2026-10-30.
- srt: sandbox-runtime 0.0.81 source, `src/sandbox/macos-sandbox-utils.ts`, read 2026-10-30.
- gh: GitHub's docs on GitHub Apps, read in their source in `github/docs` on the `main` branch, 2026-10-31: [Choosing permissions for a GitHub App](https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/choosing-permissions-for-a-github-app), [Generating an installation access token for a GitHub App](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app), and [Managing private keys for GitHub Apps](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/managing-private-keys-for-github-apps).

Irreversible: after the harm, no action restores the earlier state. A row is irreversible when its worst consequence is irreversible, for example when it lets a change skip the merge gate. Reversible: a revert, a delete, or a settings change restores the earlier state.

MVP 0.5 holds every irreversible underground row except U14 (accepted risk), U16 (no credential needs it yet), and U27 (deferred), plus U19 and U20, which keep undo and work possible. The rest is MVPF.

The auth gateway listens on the tailscale address of this mac; the inference engine runs on `v100-server`, another box on the tailnet. The sandbox reaches the gateway through its tailscale entry on the one allowlist of every role, with the port of its service (`host/roles/network-allowlist:1`), and reaches the engine only through the gateway. `render-settings` fills these entries from the owner's addresses file, refuses to start when the gateway address is on no interface of this mac (`host/sandbox/render-settings:47` to `:56`), and refuses an address without a port (`host/sandbox/render-settings:131` to `:138`), so no other port is reachable. `allowUnixSockets` lists the role's broker socket, its own state folder, and its exact text-prediction socket. Omp's native IPC code moves a socket whose path is too long into `/tmp/omp-<uid>`. The wrapper uses the pinned omp runtime and native addon to calculate that path. Both the helper and any native-cache restoration run from `/`, so they load no checkout preloads. The wrapper checks that the shared socket parent is a private folder owned by the user before launch, and grants the socket by its real path (`/private/tmp/...` on macOS): srt 0.0.81 keeps the spelling of a path that does not exist yet, and Seatbelt compares the real path, so a `/tmp/...` grant matches nothing. The sandbox can write only that prediction socket and its `.bind.lock` file, not the shared parent or another role's socket (`host/bin/omp:246` to `:261`, `host/sandbox/render-settings:129` to `:130`).|

|U9|Agent code runs on a self-hosted runner on this mac.|B|0.5|Onboarding list (`ONBOARDING.md`, check 3): GitHub-hosted runners only.|
|U28|An agent branch changes a workflow file, so CI runs it with more privileges.|A, B|0.5|The broker app has no Workflows permission (onboarding list, `ONBOARDING.md`, check 4; `docs/adr/0007-broker-github-app.md`). On 2026-10-30 GitHub refused a push of the old bot token, which had no `workflow` scope, that changed `.github/workflows/ci.yml` ("refusing to allow a Personal Access Token to create or update workflow ... without `workflow` scope"). [inference] A push of the app is refused the same way; no broker push has tested it yet. A changed `.github/**` path is also a hold: `broker merge` refuses, and the owner merges the PR on GitHub (U11).|
|U10|A bad change merges and has effects while it runs. `git revert` restores the repo content only.|A|0.5|Merge gate (`mergeRefusal`, `host/broker/protocol.ts:420` to `:432`), the only merge path of the broker: at least one CI check, every CI check `SUCCESS` (`checksRefusal`, `host/broker/protocol.ts:298` to `:307`); the head is the push record of its branch (U29); no hold (`holds`, `host/broker/protocol.ts:378` to `:386`): a `manual` on any head, each blocked head from the fourth attempt on, and a changed protected path on the head. Nothing in the broker ends a hold: `broker merge` refuses with a reason that says the owner merges this PR on GitHub (`holdRefusal`, `host/broker/protocol.ts:392` to `:406`). Then no `block` on the head, and a latest `pass` on the head from each of `code-review`, `security-review`, and `risk-review` (`headVerdictRefusal`, `host/broker/protocol.ts:408` to `:418`). The owner's approval does not merge: the owner merges every PR off the auto path on GitHub (`docs/adr/0007-broker-github-app.md`). A migrated record has no role: its `block` and `manual` count, and its `pass` counts for no role. A reviewer role gives only its own verdicts (`ROLE_VERDICTS`, `host/broker/protocol.ts:24`; `handleReview`, `host/broker/server.ts:391` to `:393`). The gate reads only the review records of its PR (`readReviewRecords`, `host/broker/review-records.ts`). `docs/adr/0006-reviewer-roles-gate.md`. Effects of merged code: onboarding list (`ONBOARDING.md`, checks 5 and 6). Each workflow that deploys, publishes, or uses secrets on `main` waits for the owner's approval in a GitHub environment, and the owner reads a merged change before the host runs it.|
|U11|A PR weakens its own review, or a merged change weakens later reviews.|A|0.5|Each reviewer session starts in its store folder `~/.ug/git/<role name>`, never in a checkout or in the omp root, which every role writes (`host/bin/omp:432`); it reads the PR only through git, so it loads no rule file, setting, or code from the repo. Its sandbox has no grant on the repo folder or the worktree folder (`host/sandbox/render-settings:164` to `:169`). Its rules are the owner's `~/.agents/roles/<binding role>/AGENTS.md`, which the wrapper passes with `--append-system-prompt` and the owner hook `role-rules.ts` gives each task subagent; the wrapper refuses a reviewer role without them and a caller's own `--append-system-prompt` (`host/bin/omp:353` to `:358`, `refuse_config_flags`, `host/bin/omp:258`). Its omp settings come from the role policy `~/.ug/omp/agent/policy.yml` in the owner part, a read-only `PI_CONFIG_FILES` overlay above omp's writable `config.yml`, which every role shares (`host/bin/omp:409`). The policy pins each setting that loads rules, skills, extensions, hooks, MCP servers, tools, prompts, memory, or notes from a path, or that keeps state across sessions, so a session cannot weaken a later one through `config.yml` (`docs/adr/0002-role-homes.md`). The wrapper refuses a policy that misses a pin (`PINNED_SETTINGS`, `host/broker/admin.ts:75`), and refuses `--config` and `--profile` for every role (`refuse_config_flags`, `host/bin/omp:258`). A setting that the policy does not pin carries from author sessions into reviewer sessions through the shared `config.yml` (`docs/adr/0009-one-omp-root.md`). Rules follow the role table at each start, so a reviewer never runs with the rules of the author role (`host/bin/omp:323`); every role uses the one network allowlist (`docs/adr/0001-accepted-risks.md`). It always starts new: the wrapper refuses each resume flag, `--session`, and each short-flag bundle with `c` or `r` (`refuse_reviewer_flags`, `host/bin/omp:277`). A change to `.github/**` or `CODEOWNERS` is a hold, so the owner merges it on GitHub (`isProtectedPath`, `host/broker/protocol.ts:346`).|
|U12|An agent approval counts as a human approval.|A|0.5|The gate counts no GitHub approval, and the broker has no verb that approves. |U13|An approval or a `pass` carries over to a newer commit.|A|0.5|Head-sha binding; the merge uses `--match-head-commit` (`handleMerge`, `host/broker/server.ts:450`).|

|U32|One agent role changes state that another role trusts: omp root, cache, temp files, git refs that a reviewer diffs against.|G|0.5|One omp root `~/.ug/omp` for every role name (`docs/adr/0009-one-omp-root.md`). The owner's role table maps each role name to its broker role and refuses an unknown name.
