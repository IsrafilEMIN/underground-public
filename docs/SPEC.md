## Onboarding checks

The owner checks each repo on GitHub before agents merge alone in it.

1. No Actions secrets and no credential variables for `pull_request` jobs. No `id-token: write`.
2. The default `GITHUB_TOKEN` is read-only.
3. GitHub-hosted runners only.
4. The broker app is a GitHub App of the owner's account, installed on selected repos, with no Workflows and no Administration permission (`adr/0007-broker-github-app.md`).
5. Each workflow that deploys, publishes, or uses secrets on `main` waits for the owner's approval in a GitHub environment. So a merge has no effect that a revert cannot undo.
6. A repo whose code runs on the host, such as underground, gets no auto merge. The owner merges each PR and reads the merged change before the host runs it.

A repo is onboarded when the owner has made these checks and installed the broker app on it: the app's installation is the list (owner decision, 2026-11-03). Until the broker rebuild, the broker also reads `~/.config/underground-broker/repos`.

Source: the earlier onboarding list, checks 1 to 6 (`git show f16005c^:docs/ONBOARDING.md`).

## Checks

**Probes of the sandbox (U1, U2).** `scripts/probe-u1-u2.sh` plants canaries on the host: a keychain item, a preference, clipboard text. Each probe runs the same read twice: on the host, then in an omp session in the arena. In the arena, `HOME` is `~/.ug/home`, so each probe of a file aims at the real home, the arena path without `/.ug/home`, and the keychain and preference probes also name the real file by its full path (`scripts/probe-u1-u2.sh`, `tests/host/probe-u1-u2.test.ts`). On the host it must succeed; if not, the probe is broken. In the sandbox the result is open (the canary is read), blocked (srt reports a denial), or inconclusive (anything else, for example a missing tool or a privacy prompt). Setup runs them on each new macOS build. Run 2026-11-03 on build 26B118: every read in the arena was refused, each with a sandbox deny in the kernel log (`THREAT-MODEL.md`, U1 and U2). The deny text reaches the probe only for plain file reads, so the probe prints `inconclusive` for the rest; the owner reads the kernel log with `log show --predicate 'eventMessage CONTAINS "deny"'` for the minute of the run. Limits: one keychain item does not cover items with other access rules, a device list does not prove capture, and a screen capture counts only if the image shows the screen.

**Tests.** The suite in `tests/` uses fake data only: temp homes, local bare repos in place of GitHub, and a fake `gh`. CI runs it on each PR head and each push to `main` (`.github/workflows/ci.yml`). Setup runs it before it writes a file or a service.

**Probes of the redesign.** `scripts/probe-arena.sh` covers the `HOME` check below. It runs after `host/bin/ug-setup`, without touching the current install, and also checks the pin hash, `omp --version` in the sandbox, a prompt through the auth gateway, and omp files in the arena. Then it tries to break out: a read and a write of the real home, the same read through omp's runtime, a symlink and a hard link from the arena, the ssh agent socket directly and through a link, and a domain off the allowlist. Every deny check has a control, and a deny counts only with the sandbox's own error; anything else is inconclusive. It lists the paths outside the arena that omp peeked at and the sandbox blocked, from the system log, calibrated by a known deny; a blocked peek passes. On 2026-11-02 these were `~/.omp/agents` and `~/.ug` (omp looks for project agents in every folder up to `/`, `findAllNearestProjectConfigDirs` in omp `config.ts`) and the macOS global preference files. `tests/host/probe-arena.test.ts` runs the probe against a leaky and a broken fake srt, and requires a BREACH or no PASS.

- `HOME`: omp, bun, and git on the pinned omp use the arena as home. A tool that ignores `HOME` fails on the srt deny; it does not leak.
- omp's helper sockets: their paths under `~/.ug/home/.omp/run/daemons`, with `lsof -nP -U | grep '/.ug/home/'`.
- The arena clone step (B4).
- Localhost inventory: `lsof -nP -iTCP -sTCP:LISTEN` on the host. Each service that listens must need a secret or be unable to do harm. On 2026-11-03: the auth broker (`127.0.0.1:8765`, bearer), the usage broker (`127.0.0.1:18765`, usage numbers only), Hex (`127.0.0.1:56939`, `401` without a password), and on every interface macOS's AirPlay Receiver (`ControlCenter`, `5000` and `7000`) and `rapportd` (Handoff). The auth gateway listens on the tailscale address. The owner runs it again when a local service is added.

**Credentials.** Each credential that an agent uses sits in `~/.ug/host`, which the sandbox cannot read (U1): the model logins, `auth-broker.token`, and `auth-gateway.token` in `~/.ug/host/auth` (B6), and the broker app key in `~/.ug/host/github-app.pem` (B7). The agent reaches models only through the auth gateway, and GitHub only through the broker. One exception, by design: the gateway bearer, which every session needs to call the gateway, sits in the session's `~/.ug/run/session.*/config/models.yml` and in `~/.ug/home/.omp/agent/models.yml` (the wrapper fills it from the config repo's `models.yml`, `host/bin/omp-arena`, and `host/arena/init` copies it; accepted in `adr/0005-model-auth-gateway.md`, U30). No other copy of a credential belongs outside `~/.ug/host`. The owner's own logins (ssh, gh, the keychain) belong to host tools, stay where those tools keep them, and stay closed to the sandbox (U1 run, 2026-11-03).

**Live run.** In a throwaway repo that passes the onboarding checks: one task from branch to auto merge, one revert with green CI through the broker, one revert with red CI by the owner on GitHub, and one PR with a planted security defect, which `security-review` must `block`.
