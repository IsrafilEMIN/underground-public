|B2a|One omp root, role names kept apart where it counts (`adr/0009-one-omp-root.md`, superseding the role homes of `adr/0002-role-homes.md`): every role name uses the omp root `~/.ug/omp` (`PI_CONFIG_DIR`). Its owner part `~/.ug/omp/agent` holds the role policy `policy.yml`, `prefs.yml`, `models.yml`, and the hooks; the role can read it but not write it. The wrapper loads `policy.yml` as a read-only `PI_CONFIG_FILES` overlay, which pins `memory.backend: off`, `autolearn.enabled: false`, and each other setting that loads rules, skills, extensions, hooks, MCP servers, tools, prompts, memory, or notes from a path, so no role leaves notes that omp loads into a later session (`adr/0002-role-homes.md`). The rest of the omp root is writable by every role: omp's own `config.yml`, `agent.db`, `history.db`, and caches, and underground's cache root, temp folder (`TMPDIR`), and state folders in `~/.ug/omp/underground`. Rules stay per binding role: the wrapper passes `~/.agents/roles/<binding role>/AGENTS.md` with `--append-system-prompt`, and the owner hook `role-rules.ts` gives task subagents the same file. |B9|Model auth gateway: run `omp auth-broker serve` and `omp auth-gateway serve --bind=<tailscale address of this mac>:<port>` on the host as launchd services, with the address from the owner's addresses file. The auth broker holds the provider logins and its bearer stays host-only. Every role shares the gateway bearer from `~/.omp/auth-gateway.token`; the gateway runs without `--clients`. The owner authorizes all roles for all served models and accounts, usage, and credential health, without per-role grants or account configuration (`adr/0005-model-auth-gateway.md`). The gateway exposes no provider secrets, auth-broker snapshots, or credential management routes. Each role's owner-part `models.yml` defines gateway providers with `transport: pi-native`, `baseUrl` the gateway's tailscale address, and `apiKey` the shared gateway bearer. The wrapper still requires every selected model to use a gateway provider or the keyless inference engine; model selections do not limit gateway authorization. The sandbox holds no provider login. The gateway bearer is readable in the sandbox and works only from the tailnet (`adr/0004-no-local-binding.md`). Usage permission alone does not integrate omp's native `/usage` command, which lacks gateway client wiring. Role isolation and GitHub reviewer restrictions remain unchanged.|U15, U30|
|B10|Three reviewer roles gate auto merge: `code-review` (does the diff solve the task, and is it sound against the whole repo), `security-review`, and `risk-review` (grades the PR as auto or manual). No reviewer role can push or open a PR. The review binding and each review record hold the role name; two role names that map to one reviewer role count as that role. `code-review` and `security-review` give `pass` or `block`; `risk-review` gives `pass` (auto) or `manual`. `broker merge` merges only on the auto path. The gate, in order: every CI check `SUCCESS`; the head is the push record of its branch (B4); no hold; the latest record on the head from each of the three roles is `pass`. The owner's approval is not part of the gate: the owner merges every PR off the auto path on GitHub (`adr/0007-broker-github-app.md`). A `block` binds to one head: a `block` on a head beats a `pass` on the same head, and a new head needs a fresh `pass` from all three roles. A hold binds to the PR, and nothing in the broker ends it: `broker merge` refuses with a reason that says the owner merges this PR on GitHub, and the owner merges it there by hand. Three things make a hold: a `manual` on any head; a changed protected path on the head (`isProtectedPath`, `host/broker/protocol.ts:336`, `~/.config/underground-broker/protected-paths`); and a fourth head of the PR with a `block`, which is the author's last attempt (B11) failed.|U10|
|B11|Review records per PR: one append-only file per PR, `~/.agents/broker/reviews/<owner>/<repo>/<pr>.jsonl`, replaces `reviews.json`. A review appends one line; the gate and `pr-status` read only the file of that PR. The broker moves each record of `reviews.json` into the file of its PR once; an old record has no role name, so its `block` and `manual` still count and its `pass` counts for no role. Records stay after the merge. `pr-status` returns every record of the PR with role, verdict, and reason, so the author can fix a `block` before the PR reaches the owner, and a reviewer can review the delta since its last `pass`. An attempt is one head with a `block` from any role; two roles that block one head are one attempt. The author's rule, in the author's rules and not in the gate: after three attempts, step back and check that the implementation solves the task, then make one last attempt. The gate counts the attempts: a fourth blocked head is a hold (B10), and the owner merges that PR on GitHub.|U10, U20|
